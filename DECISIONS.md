# ReTray Decisions

| Decision | Why it is locked |
| --- | --- |
| Start with closed-loop venues | Return is easy and the operational value is clearest. |
| Build one complete loop, not a marketplace | A complete, credible demo scores better than broad unfinished scope. |
| Use a simulated EUR 3.00 deposit | The prototype must demonstrate behavior without pretending it moves money. |
| Use Kora Kitchen, Maya L., and RT-024 | Stable shared demo data keeps every screen coherent. |
| Count one returned container as one disposable pack avoided | This is direct and does not invent a climate estimate. |
| Use charcoal and warm rose | It is a distinct operational identity that avoids generic green sustainability design. |
| Keep social links disabled without verified URLs | Never invent business accounts or contact details. |
| Reuse Sites identity headers | The existing hosting authentication provides stable user IDs without a new auth dependency. |
| Reuse Drizzle with Cloudflare D1 | The existing database adapter supports Phase A persistence and deployment migrations. |
| Keep deposits as ledger-only states | Phase A needs truthful status without claiming payment collection or release. |
| Make circulation events append-only | The return loop needs an auditable history that application code cannot rewrite. |
| Use native camera QR detection with manual fallback | It supports phone cameras without adding a scanning framework and remains usable in unsupported browsers. |
